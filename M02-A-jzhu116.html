4 Relational Table Design

The model contains three dimension tables and one job-postings fact table. Spark temporary views do not enforce primary-key or foreign-key constraints. Therefore, the workflow creates explicit surrogate keys and then checks key uniqueness and referential integrity.

Table Primary key Foreign keys Purpose
companies company_id None One row per distinct company record
industries industry_id None One row per distinct NAICS/SOC occupation combination
locations location_id None One row per distinct location and MSA combination
job_postings id company_id, industry_id, location_id One row per job posting

4.1 Create Dimension Tables

The helper below creates a null-safe natural key from each dimension’s source columns. This prevents missing source values from breaking the joins used to add foreign keys to job_postings. The assignment-provided monotonically_increasing_id() function supplies each surrogate primary key.

def add_natural_key(frame, source_columns, key_name):
    """Add a repeatable, null-safe hash key based on source columns."""
    key_parts = [
        F.coalesce(F.trim(F.col(name).cast("string")), F.lit("<NULL>"))
        for name in source_columns
    ]
    return frame.withColumn(
        key_name,
        F.sha2(F.concat_ws("||", *key_parts), 256),
    )

4.2 Create the Job Postings Table

The salary-related fields arrive as strings. The helper removes dollar signs and commas and casts only valid numeric strings. Invalid or structured strings become null rather than causing the Spark job to fail.

def numeric_or_null(column_name):
    cleaned = F.regexp_replace(
        F.trim(F.col(column_name).cast("string")),
        r"[$,]",
        "",
    )
    numeric_pattern = r"^[+-]?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)$"
    return F.when(cleaned.rlike(numeric_pattern), cleaned.cast("double"))


job_source_df = add_natural_key(df, COMPANY_COLUMNS, "_company_key")
job_source_df = add_natural_key(job_source_df, INDUSTRY_COLUMNS, "_industry_key")
job_source_df = add_natural_key(job_source_df, LOCATION_COLUMNS, "_location_key")

job_source_df = (
    job_source_df
    .join(
        companies_lookup_df.select("_company_key", "company_id"),
        on="_company_key",
        how="left",
    )
    .join(
        industries_lookup_df.select("_industry_key", "industry_id"),
        on="_industry_key",
        how="left",
    )
    .join(
        locations_lookup_df.select("_location_key", "location_id"),

        how="left",

)

4.4 Validate Keys and Relationships

The following checks compare every row count with its distinct primary-key count and count null foreign keys in job_postings. Equal row and unique-key counts show primary-key uniqueness; zero null foreign keys show that every posting matched its dimensions.

primary_key_check_df = spark.sql(
    """
    SELECT 'job_postings' AS table_name,
           COUNT(*) AS row_count,
           COUNT(DISTINCT id) AS unique_primary_keys,
           SUM(CASE WHEN id IS NULL THEN 1 ELSE 0 END) AS null_primary_keys
    FROM job_postings
    UNION ALL
    SELECT 'companies', COUNT(*), COUNT(DISTINCT company_id),
           SUM(CASE WHEN company_id IS NULL THEN 1 ELSE 0 END)
    FROM companies
    UNION ALL
    SELECT 'industries', COUNT(*), COUNT(DISTINCT industry_id),
           SUM(CASE WHEN industry_id IS NULL THEN 1 ELSE 0 END)
    FROM industries
    UNION ALL
    SELECT 'locations', COUNT(*), COUNT(DISTINCT location_id),
           SUM(CASE WHEN location_id IS NULL THEN 1 ELSE 0 END)
    FROM locations
    """
)

foreign_key_check_df = spark.sql(
    """
    SELECT COUNT(*) AS job_posting_rows,
           SUM(CASE WHEN company_id IS NULL THEN 1 ELSE 0 END) AS missing_company_keys,
           SUM(CASE WHEN industry_id IS NULL THEN 1 ELSE 0 END) AS missing_industry_keys,
           SUM(CASE WHEN location_id IS NULL THEN 1 ELSE 0 END) AS missing_location_keys
    FROM job_postings
    """
)

5.1 Query 1: Technology Salaries by Specialized Occupation

Although the prompt’s heading refers to job title, its detailed instructions specify grouping by specialized_occupation. This query follows the detailed requirement and filters to NAICS 518210.

query1_df = spark.sql(
    """
    SELECT
        i.naics_2022_6_name AS industry_name,
        i.specialized_occupation,
        ROUND(PERCENTILE_APPROX(j.salary, 0.5, 10000), 2) AS median_salary,
        COUNT(*) AS job_count
    FROM job_postings AS j
    INNER JOIN industries AS i
        ON j.industry_id = i.industry_id
    WHERE i.naics_2022_6 = '518210'
      AND j.salary IS NOT NULL
      AND j.salary > 0
      AND i.specialized_occupation IS NOT NULL
      AND TRIM(i.specialized_occupation) <> ''
    GROUP BY
        i.naics_2022_6_name,
        i.specialized_occupation
    ORDER BY median_salary DESC
    """
)

5.2 Query 2: Top Five Companies Offering Remote Jobs in California

query2_df = spark.sql(
    """
    SELECT
        c.company_name,
        COUNT(*) AS remote_jobs
    FROM job_postings AS j
    INNER JOIN companies AS c
        ON j.company_id = c.company_id
    INNER JOIN locations AS l
        ON j.location_id = l.location_id
    WHERE LOWER(TRIM(j.remote_type_name)) = 'remote'
      AND LOWER(TRIM(l.state_name)) = 'california'
      AND c.company_name IS NOT NULL
      AND TRIM(c.company_name) <> ''
    GROUP BY c.company_name
    ORDER BY remote_jobs DESC, c.company_name ASC
    LIMIT 5
    """
)

5.3 Query 3: Monthly Job-Posting Trends in California

query3_df = spark.sql(
    """
    WITH california_postings AS (
        SELECT TO_DATE(j.posted, 'yyyy-MM-dd') AS posted_date
        FROM job_postings AS j
        INNER JOIN locations AS l
            ON j.location_id = l.location_id
        WHERE LOWER(TRIM(l.state_name)) = 'california'
    )
    SELECT
        YEAR(posted_date) AS year,
        MONTH(posted_date) AS month,
        COUNT(*) AS job_count
    FROM california_postings
    WHERE posted_date IS NOT NULL
    GROUP BY
        YEAR(posted_date),
        MONTH(posted_date)

    """
)

5.4 Query 4: Salary Comparisons Across Major US Metro Areas

query4_df = spark.sql(
    """
    WITH selected_metros AS (
        SELECT
            CASE CAST(l.msa AS STRING)
                WHEN '14460' THEN 'Boston'
                WHEN '47900' THEN 'Washington DC'
                WHEN '35620' THEN 'New York'
                WHEN '41860' THEN 'San Francisco'
                WHEN '42660' THEN 'Seattle'
                WHEN '31080' THEN 'Los Angeles'
                WHEN '19100' THEN 'Dallas'
                WHEN '26420' THEN 'Houston'
                WHEN '12420' THEN 'Austin'
                WHEN '34980' THEN 'Nashville'
                WHEN '28140' THEN 'Kansas City'
                WHEN '19740' THEN 'Denver'
            END AS metro_area,
            j.salary
        FROM job_postings AS j
        INNER JOIN locations AS l
            ON j.location_id = l.location_id
        WHERE j.salary IS NOT NULL
          AND j.salary > 0
          AND CAST(l.msa AS STRING) IN (
              '14460', '47900', '35620', '41860',
              '42660', '31080', '19100', '26420',
              '12420', '34980', '28140', '19740'
          )
    )
    SELECT
        metro_area,
        ROUND(AVG(salary), 2) AS average_salary,
        COUNT(*) AS job_postings
    FROM selected_metros
    WHERE metro_area IS NOT NULL
    GROUP BY metro_area
    ORDER BY average_salary DESC
    """
)

6 Conclusion

This workflow converts the wide job-postings source into a relational Spark SQL model and validates the primary-key and foreign-key relationships before analysis. The four queries then describe compensation within the technology sector, concentration in remote California hiring, changes in California posting activity over time, and geographic salary differences. All findings are limited to the job postings represented in the dataset, and salary findings are further limited to records with usable positive salary values.
